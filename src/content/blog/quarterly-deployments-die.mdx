## The cadence problem

Quarterly deploys aren't a release schedule. They're a symptom. Usually
three symptoms:

1. Manual deployment steps that only two people can run
2. No automated verification between "it compiled" and "it's live"
3. A change advisory board treating every deploy like a moon launch

## What actually moves the needle

- **Pipeline ownership sits with the team, not a platform group.** If the
  developers don't have the keys, cadence hits a ceiling.
- **Security gates run in the pipeline, not in a meeting.** SAST, DAST,
  and dependency scans fail builds — they don't file tickets.
- **Rollbacks are boring.** If a revert takes a Friday night, deploys
  stay quarterly.
- **CAB shifts from gatekeeper to reviewer.** Pre-approved change
  categories cover the 80% path; the board handles the genuinely novel
  20%.
